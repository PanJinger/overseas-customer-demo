# 广告投放回传数据调研

调研日期：2026-08-21  
调研目的：弄清在 **小红书聚光、抖音（巨量引擎）、TikTok Ads、Google Ads** 投流后，广告主实际能拿到哪些数据、以什么粒度拿到、哪些拿不到。  
用途：支撑本仓库「多源口径不一致」的数据治理 Demo，先把投放侧数据字典的源头盘清楚。

## 先看这一段

四个平台给你的，主要不是「用户是谁」，而是 **效果报表 + 点击标识 + 你自己站点上的转化**。

| 数据层 | 你能拿到什么 | 典型形态 | 四个平台是否都有 |
| --- | --- | --- | --- |
| ① 平台聚合报表 | 消耗、展现、点击、转化、素材互动 | 后台表格 / CSV / API，按账户·计划·创意汇总 | 都有 |
| ② 点击标识 | `click_id` / `ttclid` / `gclid` | 落地页 URL 参数，用于把订单对回广告 | 都有（名称不同） |
| ③ 一方转化与线索 | 表单、私信、店铺订单、CRM | 你自己的落地页 / 店铺 / 线索接口 | 取决于你怎么接，不是平台白送用户画像 |

**看了广告但没点、没填表的人**：平台不会把姓名、手机号交给你。  
**点了广告并在你的表单里留资的人**：线索内容是你的一方数据（或平台线索通把表单推给你），不是平台把站内用户档案整包导出。

三层关系见 [示例图片/ad-data-layers-diagram.png](示例图片/ad-data-layers-diagram.png)。

## 和本仓库需求的关系

集团痛点是「抖音、小红书、Google、店铺后台各说各话」。本调研回答的是：**各平台原始字段从哪来、叫什么、粒度到哪一层**。统一口径和指标字典应建立在这些源头之上，而不是先把四个后台的「转化」加总。
